# LLM Cache 版控策略

## 為何 `data/llm_cache.json` 進入版控？

每日 CI 流程分析約 19 篇貼文，每篇需一次 Gemini API 呼叫。
若 cache 不持久化，每日重新分析相同內容會浪費配額並增加 429 風險。

將 cache commit 進版控後，跨日 cache hit 可降低 LLM 呼叫量 70%+。

## 檔案位置

`data/llm_cache.json` — key 為 `MD5(system_prompt + user_prompt)`，value 為 LLM 回傳結果。

## 體積管理

| 閾值 | 行動 |
|---|---|
| > 5 MB | 警示（CI log 顯示 WARNING） |
| > 10 MB | TODO：啟動 LRU 清理（保留最近 90 天） |

## 安全性

cache 內容為 LLM 分析結果，不含 API key 或個人識別資訊，入版控安全。
