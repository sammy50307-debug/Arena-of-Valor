## 1. 目標 (Objective) ─ 必填

修復 `analyzer/sentiment.py` 三處 post 重建（line 347/381/401）誤用 `getattr(res, "timestamp", ...)`——`SearchResult` 欄位實為 `published_date` 無 `timestamp` 屬性 → 走 LLM 的 post 時間全遺失成「時間未知」。抽 `_post_timestamp(res, default)` helper 並以**直接屬性存取 `res.published_date`**（升級 A：棄 getattr-default，欄位名錯即時 AttributeError、不靜默掩蓋），三處改用；並加**端到端契約測試**（升級 B：mock LLM 驗 published_date 真流到 analyzed_posts，防 P108.3 同類「單元過但 production 沒生效」復發）。使走 LLM 路徑的 post（含巴哈 P108.3 正規化文）時間正確流到 picker，讓 P108.3 在 production 主路徑真生效。

## 2. 觸發背景 (Why Now) ─ 必填

R-032 PoC 深挖揭露：P108.3 收官後（2026-06-06）巴哈正規化只在 local 路徑生效；production 主路徑走 sentiment（LLM），其 post 重建用錯欄位名 `getattr(res, "timestamp")`，published_date 遺失。決定性實證（`scratch/poc_dataflow_verify.py`）：模擬巴哈文 `published_date="2026-06-01 22:39:00"`，sentiment 路徑得「時間未知」、local 路徑保留。此為 R-030「最新動態不換」更深上游根因，也是 R-032 共同上游。阿喜 2026-06-07 裁示先修此根因（P108.3.1）並核准升級 A+B。
