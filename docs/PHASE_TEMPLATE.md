## 3. Entry Criteria（入口條件）─ 必填 ─ STR4

開工前必須全部 ✅：
- [ ] 前置 Phase 已收官：（列出依賴的 Phase）
- [ ] 資料/依賴已備：（列出需先存在的檔/服務/API key）
- [ ] 主公已核准：（記錄核准日期/視窗）
- [ ] 風險登記簿無未解高風險：（檢查 `docs/RISK_REGISTRY.md`）
- [ ] **驗證盲區群檢查（B-023/024/027）**：若本 Phase 改動現有行為/資料欄位/凍結計畫字面，動工前已親核真實呼叫鏈與測試契約（見下方 callout）。

> **驗證盲區群 preflight（B-023 / B-024 / B-027，P116 升級｜2026-06-14 STR8 復盤）**：近 7 Phase 最常復發的失敗模式＝「改動通過測試但 production 行為錯，因測試沒走真實鏈/契約（綠燈假象）」。改動現有行為/欄位/凍結計畫字面者，動工前必過：
> - **B-023（資料層欄位）**：grep 該欄位在所有重建/轉換層（分析/序列化/快取）的流向與欄位名一致性；關鍵欄位用直接屬性存取（拼錯即現形）非 `getattr`/`dict.get`-with-default（靜默掩蓋遺失）。多路徑系統（LLM 主路徑 vs local fallback）分別驗證。
> - **B-024（下游行為）**：改行為前先 grep「測試/契約是否已鎖定該行為」（如 `test_report_content_trust`），不只看程式消費點。
> - **B-027（凍結計畫字面）**：凍結 ≠ 正確；動工時親核真實架構呼叫鏈（誰用 `promote=False/True`、資料在哪個 scope），確認字面修法不會打破其他路徑（測試全綠可能是綠燈假象）。
> - **跨層改動**：以端到端/契約測試（非僅單元）鎖定 production 主路徑生效——「單元測試過」≠「production 生效」。

## 4. Exit Criteria（退出條件）─ 必填 ─ STR3

達成全部才算收官：
- [ ] 條件 A：（明確、可驗證，例如「66/66 測試全綠」）
- [ ] 條件 B：（量化指標，例如「token 消耗從 X → Y」）
- [ ] 條件 C：（人工驗收，例如「主公親點 5 連結全到原文」）

> **Exit Criteria 錨點規則（B-001 / B-003）**：
> - 任何建立「多端版本」架構的 Phase，Exit Criteria 必須包含「雙端 diff = 0」的機械化驗證項。
> - 任何新增或升級 skill 的 Phase，Exit Criteria 必須明列「`test_skill.py` 存在且通過 ≥ 5 個測試案例」。不存在測試 = skill 未完成。
