## 2. STR8 四問

### Q1：哪個品質層最常漏？→ **測試層(4) + 邏輯層(2)：「綠燈假象 / 驗證盲區」**

最強的復發模式（B-023 / B-024 / B-025 / B-027 四條同源）：**改動「通過」了，但 production 真實行為錯，因為測試沒走真實的鏈/路徑/契約**：
- B-023：單元測試過 ≠ production LLM 路徑生效（重建層漏接欄位）。
- B-025：查根因只查一條生產路徑（漏 production mock）。
- B-027：凍結計畫字面修法 vs 真實架構矛盾，測試全綠卻 production 回歸。
- B-024：改行為沒先查測試/契約是否鎖定。

> **這直接對應體檢 #1 高 ROI finding：`run_pipeline` 編排層零測試覆蓋**——這正是「綠燈假象 / 待 cron 終驗」反覆出現的**結構性根因**。STR8 復盤獨立收斂到同一點 = 強訊號：**下一個最該做的是補編排層 smoke 測試（體檢 #1）**。

### Q2：哪些 guard 真擋下復發？（保留 / 強化）

- **端到端契約測試**：`test_sentiment_published_date`（P108.3.1）；P108.4 改動撞上 `test_report_content_trust` 的可信度契約並被擋下 → 契約測試真的有效。
- **純函數物理共用**：`should_promote`（P111 main.py+replay 共用）防兩把尺漂移。
- **data_source 標記 + advisory checker**：`check_no_fake_stats`（P106.2）防假數據潛入。
- **數據驅動觸發**：P112 的 PROMOTE 條件防「為 0 次事件過度建設」。
→ 結論：**契約/端到端測試 + 物理共用 + advisory checker** 是被實證有效的 guard 類型，值得在未來 Phase 優先採用。
