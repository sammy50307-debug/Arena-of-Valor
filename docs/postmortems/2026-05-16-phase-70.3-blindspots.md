## 計畫書沒寫、實際撞到的問題

### B-020：報告模板的目標瀏覽器矩陣必須包含 LINE WebView

**計畫書原寫**：P63.2 起的移動版優化以桌面瀏覽器與一般行動 Chrome / Safari 行為為主要驗收，`overflow-x: hidden` 被當成防水平 scrollbar 的安全網。

**實際撞到**：LINE in-app browser 將 `html` 元素視為 viewport scroll container；`html, body { overflow-x: hidden; -webkit-overflow-scrolling: touch; }` 在 LINE WebView 中讓 touch scroll 停止轉發，導致報告整頁無法垂直滑動。桌面與一般行動瀏覽器正常，掩蓋了目標環境損壞。

**通則化**：
> 任何修改 `reporter/templates/` 的 Phase，目標瀏覽器矩陣必須包含 LINE in-app browser 實機 smoke test；桌面與一般 mobile 通過不能替代 LINE 驗收。

**已加入 / 關聯**：R-004 已登記人工 SOP；後續可補入 PHASE_TEMPLATE 的 UX/A11y 層 B 級觸發規則。

---

### B-021：template 結構性改動不會自動回補已生成報告

**計畫書原寫**：template 修補以「未來新報告正確」為主要目標，沒有把已生成靜態 HTML 視為同一產品表面。

**實際撞到**：P70.3 修復分為治本與治標：`reporter/templates/report.html` 修未來報告，另需對 `data/reports/aov_report_2026-05-*.html` 共 10 個既有主版報告套同樣 CSS patch。P70.3.1 回首頁按鈕也必須同步批次補到 10 份舊報告。

**通則化**：
> 任何 template 結構、互動、A11y 或 CSS 行為改動，都必須明確列出「未來模板」與「既有已生成輸出」兩個影響面；若舊輸出仍會被使用，收官要附 idempotent backfill 腳本或明文豁免。

**已加入 / 關聯**：R-006 已登記人工 SOP；後續 template Phase 應把 backfill 納入 Exit Criteria。

---

### B-022：動已 modified 檔案前必須先看初始 diff

**計畫書原寫**：P70.3.1 對 `index.html` 做 X2 預防性 CSS 修補時，假設 working copy 中既有 modified 內容與當前任務相容。

**實際撞到**：`index.html` 在 session 一開始已是 modified，且內容含 5 個歷史報告連結被改成 `href="#"` 的本機破壞。AI 在破壞版上疊 CSS 修補，差點 commit/push 覆蓋線上完整 landing page；後來因主公提醒才 `git diff index.html` 發現並還原。

**通則化**：
> 每次 `git status` 顯示 tracked modified 檔案時，若本 Phase 要碰該檔，動工前必須先讀 `git diff <file>`；若 diff 含無關或破壞性變更，先隔離處置，不能在未知 dirty state 上疊改。

**待加入**：PHASE_TEMPLATE 的 X2 盲區掃描 / 流程層；也應成為新視窗開局 checklist 的固定項。
