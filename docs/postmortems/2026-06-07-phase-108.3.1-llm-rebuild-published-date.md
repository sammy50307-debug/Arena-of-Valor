# Postmortem — P108.3.1：P108.3 在 production LLM 路徑失效（sentiment 重建層漏接 published_date）

- **日期**：2026-06-07
- **Phase**：P108.3.1（P108.3 補遺）
- **性質**：Blameless postmortem — 「我以為...結果不是」(G2-3) 事件
- **嚴重度**：中（剛收官的 P108.3 在 production 主路徑未生效，但已誠實標 Exit E 待驗、無浮報）

## 背景

P108.3（2026-06-06）治本巴哈 published_date 格式問題（相對/短格式 → ISO 正規化），收官時宣稱「機制已驗證（單元 + local 路徑），Exit E 端到端待 cron 驗證」，push origin/main。

## 時間線

1. P108.3 收官 push（commit c4a6afe），Exit E 標「待下次 cron 觀察」。
2. 阿喜接著開 R-032（非巴哈平台空值戰線）。
3. R-032 PoC 追資料流時，發現 published_date 經 sentiment/local 重建層「挑欄位重建」。
4. 決定性實證（`scratch/poc_dataflow_verify.py`）：模擬巴哈 SearchResult `published_date="2026-06-01 22:39:00"`，sentiment 路徑 `getattr(res,"timestamp","時間未知")` → 得「時間未知」（遺失）；local 路徑 `_get(timestamp) or _get(published_date)` → 保留。
5. 確診：P108.3 僅在 local 路徑生效；production 主路徑走 sentiment(LLM)，post 時間全遺失。

## 根因

`analyzer/sentiment.py` 三處 post 重建（347/381/401）用 `getattr(res, "timestamp", default)`，但 `SearchResult` 的欄位名是 **`published_date` 不是 `timestamp`**（無 timestamp 屬性）。getattr 的 default 機制讓「欄位名拼錯」**靜默**回 default，沒有任何錯誤 → 走 LLM 的所有 post 時間遺失成「時間未知」，被 generator `_has_known_post_date` gate 擋出 top5 池 / decay 觸底。

**雙層根因**：
1. 表層（P108.3 已修）：巴哈時間格式非 ISO。
2. 深層（P108.3 漏修）：重建層欄位名不一致 + getattr 靜默 fallback，使任何路徑的 published_date 在 LLM 重建時遺失。

## 為何沒早抓到

P108.3 的測試只驗「單元」（`_compute_decay` 對 ISO 字串生效、爬蟲 `_parse_row` 輸出 ISO），**沒有端到端驗證**「published_date 從爬蟲經 sentiment/local 重建層流到 picker」。單元測試全綠給了「已生效」的假信心，但 production 主路徑（LLM）的重建層在單元測試覆蓋範圍外。

## 修法（P108.3.1）

1. 抽 `_post_timestamp(res, default)` helper，**直接屬性存取 `res.published_date`**（升級 A）——欄位名拼錯即時 AttributeError，不再靜默掩蓋。
2. sentiment 三處重建改用 helper。
3. **端到端契約測試**（升級 B）：mock LLM 過 `analyze_posts`，斷言 published_date 真流到 analyzed_posts 的 post（涵蓋 381 LLM 成功 / 401 error / 347 showcase）。
4. 全套 467→474 passed。

## 教訓與通則化

### B-023（新 blindspot，全域連續編號）

> **修正資料層欄位前，必須驗證該欄位在所有重建/轉換層（多路徑）的流向與欄位名一致性，並以端到端契約測試（非僅單元）鎖定。存取關鍵欄位優先用直接屬性存取（拼錯即現形）而非 getattr-with-default / dict.get-with-default（靜默掩蓋遺失）。**

具體檢查點：
- 改下游消費的欄位前，grep 該欄位在所有「挑欄位重建 dict」的地方（重建層常見於分析/序列化/快取），確認欄位名一致。
- 多路徑系統（如 LLM 主路徑 vs local fallback）要分別驗證，不能假設一條路徑生效＝全部生效。
- 「單元測試過」≠「production 生效」——資料流跨層時必須端到端契約測試。

## 防復發

- 端到端契約測試 `tests/test_sentiment_published_date.py` 成為長期 guard。
- B-023 待 `cross-phase-review` / `blindspot-tracker` 評估是否納入 PHASE_TEMPLATE 開工檢查。
- 直接屬性存取模式（棄 getattr-default）作為 SearchResult 關鍵欄位的存取慣例。
